## Context

前端当前以 `/scheduler/tasks` 路由提供定时任务配置管理，调用 `/api/scheduler/tasks` 并支持 CRUD。新的日度数据服务不暴露任务配置接口，而通过 `GET /api/dashboard/daily/updates` 提供 `collection_run` 的只读运行记录。前端工作区同时存在核心 ETF Dashboard 接口适配的未提交改动，因此本变更必须避免覆盖相关文件。

## Goals / Non-Goals

**Goals:**

- 将旧任务管理页面替换为数据更新记录查询页。
- 完整映射后端区间任务筛选、分页、聚合进度和错误摘要字段。
- 支持用户选择数据类型和闭区间日期，手动异步提交数据更新任务。
- 以清晰的中文状态、日期时间和错误信息呈现采集结果。
- 保留现有路由地址，降低导航迁移风险。

**Non-Goals:**

- 不提供重试、修改或删除数据更新任务能力。
- 不改变后端调度配置或数据采集逻辑。
- 不在本变更中调整 Dashboard 核心 ETF 图表。
- 不增加自动轮询；运行中记录通过手动刷新获取最新状态。

## Decisions

### Decision 1: 使用独立的数据更新 API 模块

新增 `src/api/dataUpdates.ts`，定义查询参数、运行状态和响应结构。这样既保持页面领域边界清晰，也避免修改当前已有未提交改动的 `src/api/dashboard.ts`。替代方案是在 `dashboard.ts` 中继续扩展，但会扩大文件职责并增加合并冲突概率。

### Decision 2: 保留路由路径，替换用户可见语义

保留 `/scheduler/tasks` 和现有路由组件位置，修改中英文菜单标题及页面名称。该路径已经可能进入书签与多标签缓存，立即改名收益有限。内部 hook 和类型使用 Data Update 语义，后续如需 URL 语义化可单独增加重定向迁移。

### Decision 3: 记录只读并严格匹配后端筛选能力

筛选项包含 `data_type`、`trigger_source`、`status` 和目标日期范围；分页继续映射 `limit` 和 `offset`。虽然表格展示 `job_name`，但后端不支持该字段过滤，因此不提供误导性的任务名称搜索框。日期范围使用 Element Plus date range，一次提交成对的 `target_start_date` 和 `target_end_date`。

### Decision 4: 状态和空值在展示层转换

运行状态通过 Tag 映射为“排队中、运行中、成功、部分成功、失败”，触发来源映射为“接口、定时调度”，未知值保留原始文本以便向前兼容。日期时间统一格式化为 `YYYY-MM-DD HH:mm:ss`，空值显示 `-`。目标日期显示闭区间，进度显示完成数/总数及成功失败数；错误摘要在单元格截断并通过 Tooltip 提供完整内容，避免撑开表格。

### Decision 5: 手动提交使用独立弹窗

在列表工具栏提供“提交更新任务”按钮，弹窗内选择数据类型和目标日期闭区间。前端阻止未来日期和超过 366 个自然日的区间，调用 POST 接口后只提示“已提交”并刷新列表，不把 `202 Accepted` 误解为执行完成；任务进度仍由记录列表呈现。

## Risks / Trade-offs

- [Risk] 保留 `/scheduler/tasks` 会让 URL 与页面语义不一致。→ 优先保证兼容性，并将未来路径迁移拆成独立变更。
- [Risk] 数据类型会继续扩展。→ 下拉和类型定义按后端稳定枚举维护，当前支持 `core_etf`、`market_core`、`zhongxin_future`。
- [Risk] `running` 状态不会自动变化。→ 保留表格栏刷新按钮和查询按钮，首期不引入轮询复杂度。
- [Risk] 用户可能把提交成功理解为数据已经更新完成。→ 成功文案明确任务进入队列，并立即刷新列表显示 `queued` 状态。
- [Risk] 删除 CRUD 组件可能影响旧需求。→ 新后端不再提供对应接口；通过 OpenSpec delta 明确移除旧能力。

## Migration Plan

1. 新增数据更新 GET/POST API 类型和请求方法。
2. 将原页面重构为记录筛选表格，删除旧调度 CRUD 入口并增加手动提交弹窗。
3. 更新菜单国际化文案并保持原路由可达。
4. 执行类型检查、相关 lint 和生产构建。
5. 回滚时恢复旧页面文件与菜单文案；路由路径未变，无额外数据迁移。

## Open Questions

无。自动刷新、手动重试和路由改名均留待后续明确需求。
